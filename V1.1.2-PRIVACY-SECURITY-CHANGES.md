# v1.1.2 Privacy + Security Hardening

## Public-site changes

- Added `privacy.html` with plain-language data practices, moderation flow, retention guidance, and correction/removal information.
- Added a site-wide `no-referrer` policy to every public page.
- Removed Google Fonts. The site now uses local/system font stacks and makes no passive font request to Google.
- Removed the unused Google Maps JavaScript API enhancement and API-key configuration path. The illustrated Nine Colleges map remains; Google Maps is reached only when a visitor deliberately follows a map link.
- Removed `aria-live` from full dynamic result grids/lists; concise result-count/status messages remain live regions.
- Slightly darkened the green text token to clear the previously identified borderline normal-text contrast case.

## Dynamic-feed hardening

- Client JavaScript accepts feed URLs only when they match `https://script.google.com/macros/s/.../exec`.
- Each Apps Script endpoint accepts only its one expected JSONP callback name rather than any syntactically valid callback.
- Teaching Commons now publishes only HTTPS resource links. Plain domains are normalized to HTTPS; explicit HTTP links are rejected from the public feed.
- Public feed renderers continue to use text nodes / `textContent`, not submitted HTML.
- No public `doPost()` endpoint was added. The public feeds remain read-only.

## Google Forms hardening

The source explicitly disables:

- Google Forms response summaries
- response editing
- automatic Google email collection

For an existing installation, the maintenance functions reapply those settings without creating duplicate Forms or Sheets.

## Faculty Commons change/removal verification

Do not act on an update/removal form solely because it was submitted. Compare the request with the original private verification email. If the address does not match, or the requested change is substantial, confirm using the original address before changing the public profile.

## Retention defaults

- Events: delete or anonymize private submitter name/email within 90 days after the event ends.
- Faculty Commons: keep private verification information while the profile is active; delete or anonymize within 90 days after removal.
- Teaching Commons: keep verification/permission information while the resource is listed; after removal, delete or anonymize private contact information within 90 days unless a legitimate rights/moderation need requires longer retention.

## Existing Apps Script rollout

Updating GitHub does **not** update the already-deployed Apps Script projects. To put the server-side hardening live while keeping the current public URLs:

### Around the District Events

1. Replace the Apps Script project's `Code.gs` with `apps-script/Code.gs` from this build.
2. Save.
3. Run `setupEventSystem()` once. Because the existing IDs are already stored, it will reuse the current Form/Sheet and reapply the privacy settings instead of creating duplicates.
4. Edit the existing Web app deployment and deploy a **new version**. Do not create a different deployment URL.

### Faculty Commons

1. Replace its `Code.gs` with `faculty-apps-script/Code.gs`.
2. Save.
3. Run `setupFacultyCommons()` once. It will reuse the existing installation and reapply privacy settings to both Forms.
4. Edit the existing Web app deployment and deploy a **new version**.

### Teaching Commons

1. Replace its `Code.gs` with `resources-apps-script/Code.gs`.
2. Save.
3. Run `repairTeachingCommons()`.
4. Run `diagnoseTeachingCommons()` and verify the public-feed count is expected.
5. Edit the existing Web app deployment and deploy a **new version**.
